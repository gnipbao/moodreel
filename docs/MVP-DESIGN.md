# Moodreel MVP 设计

> 版本 0.3 · 2026-10-23 · 前置调研：[运动提取调研与原型](research/motion-extraction.md)
>
> 0.2：Moodreel 是独立开源项目，**不依赖** lemo-opuscar、Hypit 或 HyperFrames。风格包格式、渲染器、导演流程都是自己的；"按主题出片"这一半也由 Moodreel 自己完成。
>
> 0.3：**风格库采用 lemo-opuscar 的 59 套风格文档**（只导入 `STYLE.md`、`DEMO.md` 和元数据，MIT，见 `styles/`）；demo 源码、配乐、配音和渲染工具一律不搬，参考其做法自己实现，以保持代码简洁，并和以后的反推蒸馏能力共用同一套代码。渲染器先用 Puppeteer，之后基于 puppeteer-core 做加速版。绘画笔触、3D、像素、配乐驱动、真实素材这五类能力放到后期。

## 0. 一句话

输入几张风格统一的设计图和一两段同风格的视频，Moodreel 产出一个**风格包**：给导演看的规则，加上影片可以直接 import 的代码工具包。之后说一句"用〈风格〉做一个关于〈主题〉的片子"，由 Opus 5.5 担任导演，用代码画出、逐帧渲染出同风格的新片。

## 1. 目标与非目标

**MVP 目标**

- **蒸馏**：3–12 张设计图 + 0–3 段参考视频（5–60 秒，以代码驱动的 MG 为主）→ 风格包。
- **出片**：风格包 + 主题 → 15–60 秒的成片（画面 + 可选的音乐垫底）。
- 风格包里的每个数值都有出处：测量值、推导值还是推断值，来自哪张参考图或哪一秒。
- 运动语法可验证：成片渲染后，用同一套测量代码复核它是否符合风格包的运动语法。

**非目标（MVP 不做）**

- 不调用图像或视频生成模型，画面全部由代码绘制。
- 不做像素级复刻，也不复用参考的内容（角色、构图、标志、旋律）。
- 不做旁白配音、原创配乐、声音风格蒸馏和程序化音效（V1）。
- 风格库中需要以下能力的 36 套风格放到后期：绘画笔触（7 套）、3D（13 套）、像素（2 套）、配乐驱动（6 套）、真实素材（15 套）；有的风格同时需要多项。MVP 覆盖其余 23 套扁平 2D 风格。
- 不做实拍或 AI 生成视频的风格蒸馏（V2）。

## 2. 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 风格包格式 | Moodreel 自有格式：`style.json` + `STYLE.md`（11 节不变量）+ `DECISIONS.md` + `kit/` + `demo/` + `evidence/` | 规则文字给导演读，`kit/` 给影片执行；"风格 = 规则 + 可执行代码"是可复现的关键。11 节的划分参考了 lemo-opuscar |
| 导演 | Opus 5.5，以 agent skill 形式运行（Claude Code 等支持 SKILL.md 的 agent） | 视觉理解、写绘制代码、看渲染结果在同一个会话里完成，不需要额外的 API 编排 |
| 渲染 | 自研 `render/render.mjs`：页面导出 `window.DUR` / `window.render(t)` / `window.READY`，Puppeteer 逐帧截图，ffmpeg 编码，多 worker 分段并行。V1 基于 puppeteer-core 做加速版 | 已实现并通过测试片验证；"画面是时间的纯函数"让任意帧可以单独渲染、并行渲染、精确复核。本机实测 WebGL 走 Metal GPU |
| 运动测量 | `motionx`：静止帧锚定跟踪 + BIC 缓动拟合 + 语法汇总，本地运行 | 原型已验证，见调研文档 |
| 风格库 | 导入 lemo-opuscar 的 59 套风格文档（`styles/`，MIT © LemoLab，注明来源版本），标注 MVP 可做（23）或后期（36）及所需能力 | 一开源就有现成的风格可选；同时是蒸馏时的技法参照，也是往返测试的真值 |
| 技法 | 自建原语库，先覆盖 23 套 MVP 风格最常用的技法 | 只搬文档、不搬 demo 源码，技法按 STYLE.md 的描述自己实现 |
| 许可 | MIT | 借鉴 REM、motiscope、MoVer、lemo-opuscar、HyperFrames 的思路；除 `styles/` 中的 lemo 风格文档外不使用它们的代码 |

## 3. 端到端流程

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 蒸馏 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 参考图 + 参考视频
   │
 ① Intake     归一化、联系表；检查参考是否属于同一风格；用途访谈（一次问清）
   │
 ② Measure    （确定性代码）色彩 · 材质 · 版式 · 字体 · 运动语法 · 剪辑节奏
   │           → evidence/measure/*.json + 证据条带
   │
 ③ Interpret  （导演）3–5 个识别特征 / 不是什么 → STYLE.md 草稿 + LEDGER.md + 决策摘要
   │
 ◆ Gate 1     用户确认决策摘要（每项：选择、备选、依据、代价）
   │
 ④ Look       导演用原语库 + kit 写风格帧 → 渲染 → frame-check 打分 + 并排对照 → 修改（最多两轮）
 ◆ Gate 2     用户确认风格帧
   │
 ⑤ Demo       15–30 秒 demo 片，每条规则至少出镜一次，标志性动作出现一次
   │           → motion-check：重测 demo 片，与参考语法逐条比对 → 不过的反馈给导演（最多两轮）
 ◆ Gate 3     用户确认 → 存入风格库并登记

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 出片 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 ⑥ Brief      主题、受众、时长、画幅、文案或要点、品牌素材、音乐（可选）
 ⑦ Treatment  三个候选结构 → 选一个；分镜表、节拍表（每个事件落在哪一秒）；明确不照搬 demo 的结构
 ⑧ Draw       新建影片目录，复制风格的 kit，写 render(t)；先出关键帧联系表自查
 ⑨ Check      frame-check（色外面积、可读性）· motion-check（运动语法）· 文字停留时长 · 黑帧
   │           → 一轮修改
 ⑩ Deliver    渲染、混入音乐并做响度归一（−14 LUFS）、海报、CREDITS、可一键重建的源码
```

## 4. 输入规范

| 输入 | 要求 | 用途 |
|---|---|---|
| 设计图 | 3–12 张 PNG/JPG，长边 ≥ 1080，同一视觉系统（海报、关键帧、UI 截屏都可以） | 色彩、字体、版式、材质 |
| 参考视频 | 0–3 段，5–60 秒；最好是代码做的 MG | 运动语法、剪辑节奏、转场 |
| 用途 | 做什么片、给谁看、在哪发，画幅，语言 | 写 §11 变化空间、定画幅、检查字体字形覆盖 |
| 品牌素材（可选） | logo、品牌字体、品牌色 | 品牌色先作强调色；品牌字体必须覆盖影片语言 |

**风格统一性检查**：分别给每张参考图提取调色板，两两计算距离并做层次聚类。如果分成两簇以上，提示"这些参考可能属于两种风格"，让用户选一组，或明确说明要混合。

**只有图、没有视频时**：运动语法由用户在三档基调（克制 / 均衡 / 活泼）里选一档，从内置的运动预设出发，台账里全部标为"推断"。

## 5. 风格包格式

```
styles/<slug>/
├── style.json        slug、name、name_zh、version、size、fps、created、moodreel_version、refs（文件哈希和来源）
├── STYLE.md          11 节不变量（英文，给导演读），见下表
├── DECISIONS.md      Gate 1 通过的决策：选择、备选、依据、代价
├── kit/              风格的可执行部分，影片复制后直接 import
│   ├── tokens.js         调色板（含角色）、字体（族、字重、字号区间）、间距、安全区
│   ├── motion.js         GSAP 命名的缓动函数 + 实测的时长、错峰、静止、转场参数 + cubic-bezier
│   ├── texture.js        颗粒、纸纹、半调、暗角等程序化材质（参数来自测量）
│   └── moves.js          标志性动作的实现（如"14% 过冲 + 0.12 秒从左到右错峰"的入场）
├── demo/             demo 片源码：index.html + main.js + build.sh + CREDITS
├── styleframe.jpg    通过 Gate 2 的风格帧
├── demo.mp4 / poster.jpg
└── evidence/
    ├── LEDGER.md         每个数值：值、类型（观测/推导/推断）、来源（参考图#、视频秒数）、所在节
    ├── measure/*.json    palette / texture / layout / type / motion / rhythm 原始测量
    ├── checks.json       frame-check 与 motion-check 结果
    └── refs-sheet.jpg    参考联系表（仅当参考是用户自有素材时保留，见 §13）
```

**STYLE.md 的 11 节**（结构参考 lemo-opuscar）：

| 节 | 内容 | 主要来源 |
|---|---|---|
| 1 Essence | 一眼认出的 3–5 个特征；不是什么（最容易混淆的风格及分界） | 导演 + 测量证据 |
| 2 Materials & rendering | 表面、笔触、层次、边缘、纹理、光；哪些效果程序化、哪些在屏幕空间 | texture.json |
| 3 Colour logic | 规则而非色板：色数、底色、强调色只用在哪里、明度顺序、什么永远不上色 | palette.json |
| 4 Type & captions | 字体（免授权）、角色、字号区间、字幕如何属于这个风格、阅读时长规则 | type.json + layout.json |
| 5 Motion | 帧率与步进、缓动类、过冲、入场出场方式、错峰、静止；什么永远不动 | motion.json |
| 6 Camera & editing | 镜头运动词汇、镜头长度、转场类型和时长、构图规则 | motion.json + layout.json |
| 7 Sound | 乐器音色、密度、静默的用法、混音特征 | 导演提案 → Gate 1 确认（MVP 不测量） |
| 8 Signature moves | 只有这种风格会做的时刻：做法 + 适合的内容（至少三个例子） | 参考视频中反复出现的行为 |
| 9 Pitfalls | 这种媒介自带的坑和解法 | 测量推导 + 导演 |
| 10 Engine | kit/ 的文件、函数、参数，加一个不在 demo 里的最小示例 | kit |
| 11 Variation space | 每部片由导演决定的部分；三种结构、三种开场、三种结尾 | 导演 |

STYLE.md 只写对每部片都成立的规则；故事、镜头表、配乐结构等具体到 demo 的内容写在 `demo/` 的说明里，出片时不能照搬。

**风格库**有两处，导演按名称查找，先查用户的，再查内置的：

- **内置**：仓库的 `styles/`。目前是从 lemo-opuscar 导入的 59 套，用 `scripts/import_lemo_styles.py --from <lemo 检出目录>` 重新导入或跟进上游。每套的 `style.json` 记录 `phase`（mvp / later）、`needs`（painterly / 3d / pixel / music-led / real-material）和 `source`（项目、路径、commit、许可）。导入的风格还没有 `kit/` 和 `demo/`：MVP 阶段导演按 STYLE.md 用原语库画；某套风格第一次被用好之后，把它的技法沉淀成该风格的 `kit/`。`DEMO.md` 里指向上游 demo 源码的链接固定在导入时的 commit，只作阅读参考。
- **用户**：蒸馏出来的风格存在 `~/.moodreel/styles/<slug>/`，`~/.moodreel/styles/index.json` 登记。

出片时 `phase: later` 的风格要提示用户：哪项能力还没有，能做到什么程度。

## 6. 蒸馏各阶段

### 6.1 Intake

- 图片转成 sRGB PNG，长边 2048；视频转成 H.264 MP4，保留原始 fps；记录参数和哈希。
- 联系表：图片铺成网格；视频按 1 秒抽帧，标注时间。
- 根据参考的主导宽高比给出默认画幅。

### 6.2 Measure（确定性，全部本地）

| 模块 | 方法 | 产出 → 用于 |
|---|---|---|
| **palette** | 每张图在 Lab 空间做加权 k-means（k=10），合并 ΔE00 < 5 的簇，统计面积占比。角色：底色 = 边缘主导或面积最大的低彩度色；墨色 = 对底色对比度最高、面积 ≥1% 的颜色；强调色 = 彩度最高且面积 < 15% 的颜色。另外输出明度结构、彩度分布、渐变检测、WCAG 对比度 | §3、kit/tokens.js |
| **texture** | 颗粒：平坦区高通残差的标准差和频谱斜率。纸纹：背景低频起伏。半调：局部 FFT 峰值。扫描线：行周期性。暗角：径向衰减拟合。边缘：梯度剖面宽度（锐利矢量还是柔边）。阴影：硬偏移还是柔和投影（导演辅助判断） | §2、kit/texture.js |
| **layout** | 内容掩膜 → 边距、密度、居中程度；元素左边缘聚类 → 栅格列数；文字块位置分布 | §4、§6 |
| **type** | 导演读字（OCR）并判断字体类型、字重、大小写、字距；代码测文字块高度占画面高度的比例；用候选 OFL 字体渲染同样的文字，与参考裁切比对，选最接近的字体 | §4、kit/tokens.js |
| **motion** | motionx：镜头、硬切、溶解、运动段、元素跟踪、缓动拟合、语法汇总。MVP 新增：一拍二检测（运动段内与上一帧完全相同的帧占比和周期）；镜头运动（背景有纹理时 ORB 配准，扁平背景时由所有元素的共同运动反推） | §5、§6、§8、kit/motion.js |
| **motion（白盒）** | 参考本身是网页、HyperFrames 或 Remotion 工程，能拿到 URL 或源码时：在渲染器里逐帧读取 DOM 的计算样式和动画时间线（GSAP / Web Animations），直接得到精确的 tween 参数，不需要从像素反推。产出格式和像素测量一致，两条路可以互相校验 | 同上 |
| **rhythm** | 有音轨时测节拍和起音，统计剪辑点和元素 t50 落在节拍 ±1 帧内的比例（判断是否卡点） | §5、§7 |

每个数都标明观测 / 推导 / 推断；测不出来的写 `unknown`，`unknown` 不能写成规则。

### 6.3 Interpret（导演）

输入：联系表、证据条带、measure JSON，以及内置的**技法原语清单**（每个原语一行：做什么、参数、适合的风格）。

1. **ANALYSIS**：先写 3–5 个识别特征，每个都要指到证据（某张图、某一秒、某个测量值），再写"它不是什么"。
2. **STYLE.md 草稿**：按 §5 的来源表逐节写；数值必须来自 measure 或台账，数值规则一律写成区间。
3. **LEDGER.md**：STYLE.md 和 kit 中每个数值的出处。
4. **决策摘要**（Gate 1）：材质怎么实现（用哪些原语）、字体选择、声音方向、画幅；每项给出备选和代价。

### 6.4 Look：风格帧闭环

- 导演用原语库和 kit 写 1–3 张风格帧，用 `render.mjs still` 渲染。
- `moodreel frame-check` 打分：
  - 调色板覆盖：参考中面积 ≥3% 的颜色，风格帧里都要有 ΔE00 ≤ 6 的对应色。
  - 色外面积：离所有参考色都超过 ΔE00 12 的颜色，面积占比 ≤ 5%。
  - 明度直方图的 EMD；材质统计偏差（颗粒、暗角、边缘锐度）。
  - V1 加入风格嵌入相似度（CSD）。
- 生成参考与成品的并排图；导演修改一轮后交给用户（Gate 2）。两轮还不对，就回到 Gate 1 重新选材质方案。

### 6.5 Demo 与运动复核

- 15–30 秒，每条规则至少出镜一次，标志性动作出现一次。
- `moodreel motion-check`：用 motionx 测 demo 片，与参考语法逐条比对（借鉴 MoVer 的谓词和 REM 的逐条判定）：

| 断言 | 默认容差 |
|---|---|
| 入场时长中位数 | 参考的 ±25% |
| 入场主导缓动类占比 | ±20 个百分点 |
| 过冲比例；过冲幅度 | ±25 个百分点；参考 p25–p75 的 1.5 倍以内 |
| 出场比入场短（如果参考如此） | 顺序关系成立 |
| 错峰间隔（如果参考有） | 至少一组，间隔在 ±30% 以内 |
| 静止时长中位数 | ≥ 参考的 0.8 倍 |
| 镜头长度中位数；转场类型 | ±35%；不出现参考和 STYLE.md 都没有的转场类型 |
| 运动密度 | ±0.15 |

- 不通过的断言连同证据条带反馈给导演，最多两轮。

### 6.6 Pack

Gate 3 通过后，`moodreel pack`：校验名称不重名、`demo/build.sh` 能在临时目录重新构建、STYLE.md 和 kit 中的数值都能在 LEDGER 里找到出处，然后写入风格库并登记。

## 7. 出片

出片是 Moodreel 自己的导演流程（skill 的另一半），不依赖外部工具：

- **Brief**：一次问清主题、受众、时长、画幅、文案或要点、品牌素材、是否有音乐；其余用合理默认值。
- **Treatment**：先写三个候选结构（例如单线旅程、前后对比、倒计时、清单反转），选一个并说明理由；分镜表（景别、机位、运动、时长、为什么）；节拍表；把 demo 的结构放在旁边对照，不能照搬。
- **Draw**：`films/<name>/` 下新建 `index.html` + `main.js`，复制风格的 `kit/`（影片目录自包含，风格包以后更新也不影响旧片）。先渲染关键帧联系表自查构图、可读性和色外面积。
- **Check**：frame-check、motion-check、文字停留时长（每段文字从完整出现起，停留时间要够读完：中文约 4.5 字/秒，其他约 15 字符/秒，再加 1.5 秒）、黑帧和空白帧。一轮修改。
- **Deliver**：`render.mjs video` 渲染；有音乐时用 ffmpeg 两遍 loudnorm 归一到 −14 LUFS 再合成；输出 `<name>.mp4`、`poster.jpg`、`CREDITS`（所有第三方素材及许可）和可一键重建的源码。

## 8. 评测

| 层 | 方法 | MVP 验收线 |
|---|---|---|
| 运动测量 | 测试片扩充到 10 条以上：现有 mg-basic，加镜头推拉、一拍二、逐字动画、旋转、描边生长、文字密集、深色背景、竖屏；每条都有干净版和压力版 | 召回 ≥ 90%；t50 在 1 帧内 ≥ 85%；方向类 ≥ 80%；**认定的缓动族认错率 ≤ 5%** |
| 往返测试 | 从风格库的 23 套 MVP 风格中挑 5 套差异明显的，按其 STYLE.md 用 Moodreel 渲染影片（真值就是那份 STYLE.md），再把影片和截图作为输入去蒸馏，逐节对比产出的 STYLE.md 和原版，并比较两版影片的运动语法 | 11 节中 ≥ 8 节被判为同一风格；运动断言 ≥ 80% 通过 |
| 风格帧 | Gate 2 两轮内通过的比例；frame-check 分数和人工判断的一致性 | ≥ 70% |
| 端到端 | 同一风格做 3 个不同主题，盲评是否"像参考" | 3 个里 ≥ 2 个被认为同风格 |

往返测试渲染出的影片同时也是开源仓库里的示例和教程素材。

## 9. 导演的职责与 skill 结构

分工：**代码负责测量、打分、渲染、打包；导演负责理解、取舍、命名、写规则和写绘制代码。**

```
skills/moodreel/
├── SKILL.md                     两条流程（蒸馏、出片）、闸门、"每个数都有出处"的纪律
└── references/
    ├── distill/
    │   ├── intake.md            参考统一性检查、用途访谈
    │   ├── reading-evidence.md  怎么读联系表、证据条带和 measure JSON
    │   ├── writing-style-md.md  11 节逐节的来源和措辞（只写规则，数值用区间）
    │   └── checks.md            frame-check 和 motion-check 的读法与修改策略
    ├── produce/
    │   ├── brief-and-treatment.md
    │   ├── drawing.md           render(t) 页面契约、确定性规则、kit 用法、原语库
    │   └── delivery.md          检查清单、音乐与响度、CREDITS
    └── primitives.md            技法原语清单
```

需要用户参与的只有蒸馏的三个闸门和出片的一次 brief，其他时候不反复追问。

**确定性规则**（写进 drawing.md）：不用 `Date.now()`；`Math.random()` 必须用带种子的生成器；不保留帧与帧之间的状态；任何一帧都能单独渲染。

运动测量的扩展顺序（每一项都是一个新的"属性读取器"，拟合、认定和语法汇总共用）：旋转 → 单轴拉伸（柱子生长、下划线展开）→ 遮罩擦除和裁切揭示 → 描线生长 → 逐字和打字机 → 数字跳动（OCR 读值）→ 循环、粒子和环境动效（测周期和速度分布）→ 3D 和着色器（只测镜头和节奏）。

## 12. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 复杂运动测不出来（镜头、3D、逐字、粒子） | §5、§8 偏弱 | 测不了的由导演读证据条带写定性规则，标为推断；按 V1 路线逐类补齐（见调研文档 §5） |
| 测量参数是在单条测试片上调的，存在过拟合 | 真实素材上效果下降 | W1 先扩充测试片并加入真实参考，再冻结参数 |
| 风格库只有文档、没有技法代码，材质模仿全靠原语库 | 风格帧不像 | MVP 收窄到 23 套扁平 2D 风格；原语库按这些风格的高频技法优先实现；frame-check 加人工闸门；风格用好一次就沉淀成它自己的 kit |
| 上游 lemo-opuscar 更新风格文档 | 内置风格落后 | 导入脚本可重复运行，按 commit 跟进；导入前对比差异，人工确认 |
| 出片这一半也要自己做，工作量变大 | 工期 | MVP 不做配音和程序化音效，音乐只支持用户提供的音轨 |
| 参考之间风格不统一 | 蒸馏出四不像 | Intake 做统一性检查 |
| 导演写进主观或错误的数值 | 风格漂移 | 台账强制每个数都有出处；pack 前校验 |

## 13. 许可与合规

- 只提取语法（节奏、配色逻辑、运动规律），不复用内容：不照搬角色、设计、旋律、镜头、标志和字体设计。
- 参考素材留在本地，不进入风格包；只有用户声明是自有素材时，才保留参考联系表。
- 网络参考片只在本地测量，不上传到任何云端模型。
- 字体和材质资源只用 OFL、CC0、CC BY，记录在 `CREDITS`。
- 借鉴的开源项目在 README 中致谢。`styles/` 中的 lemo-opuscar 风格文档按 MIT 保留版权和许可声明（`styles/LICENSE-lemo-opuscar`），每份文档注明来源 commit；除此之外不复制它们的代码。上游 demo 片和静帧是 CC BY 4.0，没有导入。
